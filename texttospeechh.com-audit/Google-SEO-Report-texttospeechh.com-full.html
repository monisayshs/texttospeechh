2. Audit Categories

2.1 Technical SEO

Score: 68/100

What Works

  • HTTPS enforced with 308 non-www->www redirect and Strict-Transport-Security
  • Clean robots.txt with allow/disallow rules and sitemap reference
  • All 36 live pages emit a self-canonical
  • 404 pages correctly return HTTP 404 with noindex, follow
  • Vercel CDN caching and Brotli compression (Content-Encoding: br)

Findings

11 broken URLs (9 unique targets) return HTTP 404 Critical

Footer links on every page point to /cookie-policy, /dmca, /language/french and /language/german which all return 404. The homepage additionally links to /accessibility, /community-guidelines, /blog/ultimate-ai-texttospeechh.com-guide and /blog/text-to-speech-audiobook-creation (404). Blog post /text-to-speech/blog/text-to-speech-for-students links to dead /text-to-speech/txt-to-speech.

Recommendation: Create the missing legal/locale/community pages, or 301-redirect each dead URL to the nearest live equivalent (e.g. /cookie-policy -> /privacy-policy). Remove the four dead /blog/* footer links.

Sitemap contains 4 dead URLs, 9 redirecting URLs, and omits real blog posts Critical

sitemap.xml lists /blog/text-reader, /blog/ultimate-ai-texttospeechh.com-guide, /blog/ai-voiceover-for-youtube-shorts and /blog/text-to-speech-audiobook-creation (all 404). Nine /blog/* URLs 308-redirect to /text-to-speech/*. The five live blog posts (/text-to-speech/blog/best-ai-voices, elevenlabs-alternatives, how-text-to-speech-works, text-to-speech-for-students, text-to-speech-for-youtube) are not in the sitemap at all.

Recommendation: Regenerate sitemap.xml from live URLs: drop dead URLs, list only final /text-to-speech/* URLs, add all blog posts, keep the blog hub and tool pages. Re-submit in Search Console.

Canonical host inconsistent with redirect target High

All inner pages canonicalize to https://texttospeechh.com/... (non-www), but that hostname 308-redirects to https://www.texttospeechh.com. The homepage canonical correctly uses www. Google must follow the redirect to reconcile the canonical.

Recommendation: Update canonical tags on every inner page to https://www.texttospeechh.com/<path> and update the Organization/WebSite/SoftwareApplication schema 'url' fields likewise.

Security headers incomplete (no CSP, X-Frame-Options, X-Content-Type-Options, Referrer-Policy) Medium

Only Strict-Transport-Security is returned. No Content-Security-Policy, X-Frame-Options, X-Content-Type-Options, Referrer-Policy or Permissions-Policy. Not a direct ranking blocker but weakens trust and click-through signals in some contexts.

Recommendation: Add X-Frame-Options: DENY, X-Content-Type-Options: nosniff, Referrer-Policy: strict-origin-when-cross-origin and a CSP in vercel.json headers.

Robots.txt Sitemap line references non-www hostname Low

robots.txt declares 'Sitemap: https://texttospeechh.com/sitemap.xml' (non-www), which 308-redirects to www.

Recommendation: Update to https://www.texttospeechh.com/sitemap.xml.

2.2 Content Quality

Score: 70/100

What Works

  • Primary page scored 96/100 on QRG-aligned content quality (density 1.0, 5,941 tokens)
  • FAQ content is visible on-page (matches FAQPage schema)
  • 1871-word in-depth guide on the primary page with structured headings and a comparison matrix
  • Unique meta descriptions on every page

Findings

12+ thin pages under 300 words High

Language pages (222-234 words: /language/english, hindi, spanish, urdu), tool landing pages (231-284 words: /text-to-speech/voice-generator, word-to-speech, read-aloud, pdf-to-speech, online-text-to-speech, text-to-voice, free-text-to-speech), and /contact (284) carry minimal unique content and are likely doorway-style.

Recommendation: Expand each tool/language page to 800+ words with unique use-case guidance, FAQ, and examples, or merge and redirect thin variants to the closest canonical page.

Doorway-pattern /keyword/* URLs redirect to tool pages Medium

/keyword/free-ai-texttospeechh.com and /keyword/text-to-speech-free 308-redirect to /text-to-speech and /text-to-speech/free-text-to-speech. Keyword-stuffed paths are a Google doorway-page pattern and waste crawl budget.

Recommendation: 301-remove the /keyword/* URLs (or make them noindex) and ensure all internal links point directly to the canonical /text-to-speech/* paths.

Readability is very low (Flesch-Kincaid grade 15.2, FRE 16.0) Medium

The primary guide reads at post-graduate level with dense jargon (Tacotron 2, HiFi-GAN, WaveNet). Average sentence ~17 words, 84.6% of content is multi-syllable. This limits ranking for mass-market 'text to speech' queries.

Recommendation: Add a plain-language summary and shorten complex sentences; introduce sub-headers with scannable bullets and a TL;DR box aimed at a grade 8-9 reading level.

Weak E-E-A-T: no named author, no author bios, domain 9 days old Medium

Article schema author is the Organization 'TextToSpeechH AI' with no person byline, no author page, and no publish date rendered in HTML (JSON-LD only). Domain registered 2026-07-27 (Hostinger). sameAs points only to an Instagram profile.

Recommendation: Add named human authors with bios and credentials for each blog post, show visible publish/modified dates, expand the About page, and grow legit off-site mentions.

2.3 On-Page SEO

Score: 78/100

What Works

  • Every page has a unique title tag, meta description, canonical, and a single H1
  • Clean heading hierarchy (one H1, logical H2/H3 structure)
  • lang="en" set, Open Graph and Twitter Card meta present
  • Internal linking to tool pages, language pages, and blog from the primary page

Findings

Title tags too long on ~30 pages (66-88 chars) High

Most titles exceed 60 chars and will truncate in SERPs, e.g. how-text-to-speech-works (88), elevenlabs-alternatives (82), text-to-speech-for-students (82). Brand suffix '| TextToSpeechH AI' pushes keywords past the limit.

Recommendation: Trim titles to 50-60 chars keeping the primary keyword first and shortening the brand suffix.

Some meta descriptions over 160 chars Medium

/privacy-policy (233), /terms (180), /about (198), /text-to-speech (161), and 3 others exceed the display limit and will be truncated in SERPs.

Recommendation: Rewrite descriptions to 140-158 chars with a clear call-to-action.

Hreflang locale targets are all 404 and not reciprocal Critical

Every page declares hreflang alternates to https://texttospeechh.com/uk, /ca, /au, /hi, /de, /fr, /es, /ja, /pt - all return 404. The existing /language/* pages (english, hindi, spanish, urdu) are not referenced. No self-referencing hreflang and no x-default localization.

Recommendation: Until localized sites are live, remove the hreflang block entirely. When built, point hreflang at the actual locale URLs (e.g. /language/french), add reciprocal tags on each locale page, and include a self-referencing entry plus x-default.

No visible publication date or author on blog posts Low

Article dates exist only in JSON-LD; no <time> or visible byline, reducing freshness signals in SERPs.

Recommendation: Render a visible publish date and author byline on every article.

Findings

Article.author and publisher both resolve to 'TextToSpeechH AI'. Google prefers named Person authors for article rich results and E-E-A-T.

SoftwareApplication lacks aggregateRating and review data Low

The app schema has name/url/operatingSystem/applicationCategory/offers but no aggregateRating, review, or screenshot/image properties that would qualify for richer presentation.

Recommendation: Add aggregateRating/review only once real user reviews exist, plus a screenshot image.

Organization schema has a single sameAs and no address/contact page Low

sameAs lists only the Instagram profile; no telephone, address, or founder info. Weakens local/entity disambiguation.

Recommendation: Add additional legit sameAs profiles and a physical/registered address when available.

2.5 Performance (Core Web Vitals)

Score: 65/100

What Works

  • CLS 0.0 (no layout shift detected)
  • Very small page: ~213KB transfer, 11 main-document resources, single stylesheet + single script
  • Brotli compression and CDN caching via Vercel
  • TTFB ~703ms from our lab environment

Findings

FCP and LCP ~2.7s - likely 'Poor' on mobile High

Lab run (desktop viewport) shows first paint/FCP ~2688ms and LCP ~2688ms, above the 2.5s 'good' threshold. The 169KB Google Analytics gtag script and Microsoft Clarity load early and compete with the hero render.

Recommendation: Defer analytics with requestIdleCallback or load after load event; preload the LCP element; move Clarity behind idle time. Verify with PageSpeed Insights once an API key is configured.

Render-blocking Google Fonts request Medium

Inter font via Google Fonts is fetched render-blocking (47KB woff2). No font-display: swap or preload of the LCP font.

Recommendation: Add font-display=swap (already present), preload the woff2, or self-host the font subset.

No lazy loading or resource hints for core assets Low

0 lazy-loading images and no preload/dns-prefetch for app.js/style.css. Minor given the tiny payload, but preload of above-fold assets would cut FCP.

Recommendation: Preload app.js and style.css, and lazy-load any below-fold images once content imagery is added.

2.6 AI Search Readiness

Score: 55/100

What Works

  • robots.txt allows all AI crawlers by default (no GPTBot/ClaudeBot blocks)
  • Long-form content with clear H2 structure is naturally citable
  • FAQPage and Article schema improve machine comprehension
  • Clean, semantic HTML headings help LLM extraction

Findings

No llms.txt or llms-full.txt file High

https://www.texttospeechh.com/llms.txt and /llms-full.txt both return 404. LLMs have no curated index of the site's key pages for citations.

Recommendation: Publish an llms.txt with the tool homepage, key tool pages, and top blog articles with one-line summaries, plus an llms-full.txt with condensed page content.

No external citations, sources, or named authors to build citability trust Medium

Articles cite no sources, studies, or external links; content reads as AI-generated. Domain is 9 days old with no backlink/authority footprint, so LLM answer engines have little reason to cite it.

Recommendation: Add real sources/footnotes, named expert authors, and earn off-site mentions (Reddit, ProductHunt, tutorials) that LLM crawlers can pick up.
