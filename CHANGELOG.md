## [Unreleased]

### Fixed
- **PDF upload extraction fixed for ReportLab PDFs (2026-11-06)** (`src/services/fileParser.js`): production `POST /api/upload` rejected every ReportLab-produced PDF with "Unable to extract readable text from the uploaded PDF document" — the owner hit it himself with the daily SEO report PDF. Root cause: ReportLab writes its content streams with the filter chain `/Filter [ /ASCII85Decode /FlateDecode ]`, but the dependency-free production engine (pdf-parse v2 cannot load in the edge runtime) only attempted a raw FlateDecode: zlib inflate failed on the ASCII85 text, the smart engine returned '', and the legacy engine (which also only inflated) returned '' too. Shorter/plain Flate-only PDFs worked, which is why the bug hid. Fix: stream bytes now decode through the declared `/Filter` chain in order — a new dependency-free ASCII85Decode (with the `/AHx` and `/Fl` abbreviations) feeds the existing guarded zlib inflate; an unsupported filter yields an empty stream instead of undecodable bytes; the legacy last-resort engine applies the same chain via the dictionary preceding each stream. The no-ToUnicode decode fallback also gained the WinAnsiEncoding 0x80–0x9F map (em dash, bullets, curly quotes) and ReportLab's 0x7F bullet, so standard-font text no longer carries C1 control characters. Verified on a 117-PDF corpus from ~/workspace/seo through the production path (pdf-parse bypassed): readable extraction 25/117 → 116/117 with zero regressions; the one holdout is a WeasyPrint PDF 1.7 whose page dictionaries live in compressed object streams (/ObjStm + xref stream), which this engine has never indexed (it failed before this change too). The owner's file now extracts 10,205 chars containing "Daily SEO Report"; the symbol-soup garbage guard still rejects undecodable font encodings; TXT/DOCX paths untouched. Live-verified on production `/api/upload` after deploy.
- **Voice-cloning hero image optimized (2026-11-05, owner-approved D2)**: `is-ai-voice-cloning-legal-hero.webp` recompressed 417,762 B → 100,866 B (2048×1152 → 1600×900, WebP q80, visually verified against the original); original backed up outside the repo in the project folder.
